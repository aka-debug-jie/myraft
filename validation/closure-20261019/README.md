# 本轮收尾验证（2026-10-19）

起点为 81723b8，开始时工作区干净。原 `validation/benchmark` 的 80 轮结果保持逐字节不变；此目录为新实现的独立验证。新实验的环境文件记录基线提交和 dirty=true，并以源码 SHA-256 绑定实际构建，不能仅凭提交号把它当作旧源码测量。

- `checks.json`：本轮实际执行的检查，明确未执行项。
- `benchmark/`：10、20、50、100 节点四场景各一轮的新结果；环境中的实际输出路径已替换为项目相对路径，其他运行参数和源码/二进制摘要保留。原始节点日志和数据保存在本地 `.test-output/closure-20261019`，不纳入公开版本。
- `performance.json` 与 `perf-*.txt`、`idle-*.txt`：同 Linux 主机、Go 1.27.2 的前后微基准。每组重复三次；提交测试每次迭代以 128 条为一批提交完整的 2101/21010 条日志。sync-only 包括元数据的创建、写入、Sync、关闭、rename，不是单独的 fsync 系统调用计时。没有减少同步次数。
- `race-final.txt` / `repeated-race.txt` / `python-final.txt`：本轮测试输出。

复现失败和修复后的原始工作记录保存在工作区的私有工具记录目录，未把包含用户路径和 Windows 会话元数据的日志放入此目录。Windows 启动验收在已有虚拟机 SYSTEM 会话执行；旧版本数据先复制到独立目录，再由新源码恢复并核对原 index/hash/x，原文件没有删除或改写。

微基准的收益不等于整个集群的吞吐收益；本轮每规模每场景仅一次，不能声称稳定性能或用它与旧 Win11 的五轮均值作性能前后比较。
