# Phase 1：交互修复与集群 Hero / KPI

基线 `c9bf336`，生产实现提交 `3fe7188`。本轮在 Phase 1 评审处停止，SVG 为主版本，Flow/compare 保留；未进入节点视觉重构。

## 实际修复

- 会话菜单与手机导航互斥；可用 Escape、外部点击关闭，选择操作后收起。打开时键盘焦点进入菜单，关闭时回到触发器，Tab 离开不被拉回。
- 取消确认对话框恢复原触发器焦点；触发器消失或处于禁用状态时回到会话入口。
- 当前校验只保留顶栏一个入口；提交命令没有复制到 Hero。
- 比较模式共享选择，但仅最近操作画布拥有节点 Tab 入口。指针选择另一画布时转移归属。
- HTTP 即时回执和 SSE 任务使用同一列表。SSE 接管后优先展示后续状态，记录滑出窗口也不会复活旧 queued 回执。
- 同 ID 换 Term/instance 保持位置，确认状态重新等待两个独立快照；补充说明与测试，没有改几何或选举规则。

## 指标含义

Hero 展示会话、观测到的 Leader/Term、可达数量、采样年龄和异常状态。前五张卡来自当前唯一有效 Leader 的本地观测：Leader、Term、CommitIndex、LastApplied、精确整数 x。它们不是全体一致性证明；无唯一有效 Leader、身份异常影响该 Leader、断线或过期时显示未知。其他节点身份异常和可达数量分别表达。

监控 RPC/s 为同一 controller/session/generation 的相邻完整快照中 `monitor_rpcs` 的差值除以服务端采样时间差。计数包含控制台 Status、EventRange 和完整校验的请求尝试，不是节点间 Raft 吞吐、成功 RPC 数或多数派授权。首次采样、重置、无效时间差和过期不填假值；重复帧不重复计算，也不清除已经算出的有效速率。

Go、协议、HTTP API、SSE/client、请求受理及未知写入不重试规则均未改；没有增加监控请求、依赖或外部字体。监控计数的 TS 类型与既有精确 JSON 解析一致地容纳整数原文字符串。用户的未提交设计文档保持原样。

## 验证

详细结果、前后记录和截图见 [本轮证据](../validation/frontend-phase1-20261024/README.md)。

- 先复现6类交互缺陷，再运行修复后的12项浏览器检查。
- TypeScript、生产构建、26项单元测试通过。
- 现有30个布局组合和7组交互回归通过；生命周期两版各60次更新没有丢边，预热后的节点、监听器和SSE数量稳定。
- SVG和Flow各完成真实11节点课堂流程，22个节点通过独立算术参考：2101命令、校验、检查点、Leader故障、再提交3条、原盘恢复、历史校验和导出。
- 真实11/100节点的六项KPI逐项与同批SSE数据对照；异常、空、加载状态另用显式合成数据测试。
- 同机三轮更新和拖动比较，没有出现多数轮次P95退化超过20%。显示确认耗时包含两次requestAnimationFrame，不能当作纯CPU耗时或Raft延迟；不报告可靠P99。

原课堂脚本现在会在启用控制后重新打开会话菜单，这是菜单“选操作后关闭”的新行为；未删除断言。开发中发现的新测试误将“尚未启用控制时创建应可用”作为期望，已纠正为创建必须禁用；另修正测试选择器和加载截图收尾问题，原始失败输出保留。
