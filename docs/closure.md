# 81723b8 后的收尾修复说明

工作区从 `81723b8` 开始，初始无未提交修改。基线 Go 1.26.3 单元测试和原 Python 回归通过。本轮使用 Go 1.27.2 做 Linux 回归与性能对比；Win11 使用既有 Go 1.26.3 做兼容性和启动验收。没有推送远端，没有删除旧实验数据，也没有更改固定成员、net/rpc、WAL v2 或已有 CLI。

## 安全性测试补齐

`benchmark.py` 在故障和追赶前保存固定的 index/hash/x。多数派提交后、旧节点恢复后、空节点追赶后均与原检查点比较。断言层反例让各节点最终状态完全相同但历史前缀被替换，检查器必须拒绝；这证明检查能力，不表示 Raft 曾实际丢失已提交数据。

`partition_test.go` 通过六条有向 TCP 测试代理，关闭已有持久连接并阻断新连接；不修改运行节点的 peers。旧 Leader 少数派写入超时而保留未提交尾部，多数派新 Leader 提交冲突日志，恢复后修复尾部、保持旧提交前缀，并能再次提交。最终 x 由独立算术应用函数核对。命令生成仍使用同一固定种子生成器；该参考检查验证复制/应用，不单独证明生成器正确。

## 有限优化及实测

`advanceCommitLocked` 无待提交日志时直接返回；无 matchIndex 进展的回复不再排序。仍保留简单排序和当前任期提交条件。

`commitLocked` 对不可变已提交前缀维护增量 SHA-256。每条编码仍是原 `json.Encoder.Encode` 加换行，未改 WAL 或已有摘要格式。恢复重建一次；存储失败不发布新 commitIndex/committedHash/x，节点进入失败状态，不能继续使用已推进的累积摘要。测试与全量 logHash 对照了空日志、分批提交、未提交冲突替换、重启续写、保存失败及失败后恢复。

同一 Linux 主机、Go 1.27.2，三次重复的中位数如下；完整原始微基准在 `validation/closure-20261019`。

| 操作 | 修改前 | 修改后 |
|---|---:|---:|
| 100 成员空闲提交检查 | 5.953 µs，896 B/1 次分配 | 2.426 ns，0 分配 |
| 2101 条，128 条/批，完整提交过程 | 48.810 ms | 12.959 ms |
| 21010 条，128 条/批，完整提交过程 | 3332.720 ms | 101.265 ms |
| 2101 条对应的仅元数据同步写入 | 9.492 ms | 10.208 ms |
| 21010 条对应的仅元数据同步写入 | 80.704 ms | 86.109 ms |

空闲路径接近无工作循环，不能把该比值解释为集群加速倍数。提交微基准包含哈希、元数据同步和状态应用；仅元数据组包含文件创建、写入、Sync、关闭及 rename。同步次数没有减少；仅元数据组未出现收益，而累计全量编码/哈希的开销显著减少。没有添加未提交尾部缓存，也不以这些微基准声称端到端集群吞吐提升。

## 复现与交付边界

```shell
go vet ./...
go test -count=1 ./...
go build -o raft-node .
go test -race -count=1 ./...
python -m unittest discover -s scripts -p 'test_*.py'
python scripts/smoke_test.py --nodes 3 11
python scripts/benchmark.py --nodes 10 20 50 100 --entries 2101 --rounds 1 --seed 42 --timeout 120
```

Windows 构建程序名为 `raft-node.exe`；启动和目录恢复方式见 README。`scripts/test_start.ps1 -WorkRoot 新目录` 可复现启动验收；原始覆盖缺陷用其 `-BaselineOnly` 模式配合 81723b8 脚本复现。新代码会拒绝旧缺陷，因此不应在新版本上期待 BaselineOnly 通过。

新基准入口每次构建一个本轮独占二进制，保存 Git 提交/dirty、必要源码与程序 SHA-256、实际工具版本、参数和测量口径；完整尝试与中断/清理失败分开记录。原 80 轮结果与原报告保留。当前 16 轮规模结果及检查表见新报告和 `validation/closure-20261019`；不能把旧 PASS 归给新源码。

本轮已通过 Go fmt/vet/test/build、Linux 全包 race、关键用例三次 race、Python 十项回归、历史检查点三次重复、3/11 节点 smoke、Win11 新目录 11 节点 2101 命令，以及 81723b8 WAL v2 数据副本的恢复和旧前缀核对。Windows race 未执行（缺 C 工具链），未登录原桌面做手工关窗；窗口相关验收限 SYSTEM 会话的进程启动与状态验证。原始旧数据未改动。

仍无动态成员、快照、请求去重、线性一致业务读取或生产安全框架。磁盘 Sync 仍在锁内，WAL 持续增长。计时器单元测试和小集群分区测试不证明任意网络条件下的全部活性；单机规模实验每场景仅一轮，不能给出稳定尾延迟结论。
